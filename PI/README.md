# PI — 라즈베리파이 자동 조준 포탑

라즈베리파이4에 붙은 카메라로 타겟(공 + 막대 + 받침)을 찾고, **색으로 아군/적군을 구분해 적군만** 조준·발사하는 코드다.
타겟 검출 모델(YOLO)은 [YOLO/](../YOLO/)에서 학습하고, 이 폴더는 그 모델을 받아 **촬영 → 검출 → 색 판정 → 조준 → 발사**를 한다.

```
카메라 1280×960 ─▶ YOLO 검출(NCNN) ─▶ 박스 안 색 측정 ─▶ 아군 / 적군 / 판정 불가 ─▶ 조준점으로 서보 이동 ─▶ 발사
 colorlab/camera.py   pipeline/tools/target_pipeline.py    colorlib.py, color_refs.json        aim_table.json, 07_aim_calib.py
```

- 장비: Raspberry Pi 4 Model B 4GB, Raspberry Pi OS Bookworm 64-bit, Camera Module v1(ov5647), SG90 서보 3개(yaw, pitch, 발사)
- 화면: VNC(wayvnc)로 데스크톱에 접속해 OpenCV 창으로 본다.
- 현재 검출 모델: **r4** (`pipeline/weights/ncnn_r4/`)

## 2. 설치

### 2-1. 카메라·촬영용 (01~05, 98)

picamera2는 **apt로 설치된 시스템 패키지**를 쓴다. `pip install picamera2`는 하지 않는다.

```bash
sudo apt update
sudo apt install -y python3-picamera2 python3-opencv python3-numpy python3-pil
sudo apt install -y fonts-nanum              # 선택: 화면 글자를 한글로
cd ~/src && python3 02_check_colorspace.py   # → ALL PASS 면 정상
```

서보는 **pigpio**로 제어한다(`import pigpio`). 서보를 쓰는 스크립트(05, 07, 98)를 실행하기 전에 pigpio 데몬이 켜져 있어야 한다(`sudo pigpiod`).

### 2-2. 검출·조준용 (07, 08, run_match)

YOLO 검출에는 ultralytics와 ncnn이 필요해서 별도 venv(`pipeline/venv`)를 쓴다. 실제로 설치해 동작을 확인한 순서다.

```bash
cd ~/src/pipeline
python3 -m venv --system-site-packages venv      # apt의 picamera2를 그대로 쓰기 위해
venv/bin/pip install --upgrade pip
venv/bin/pip install torch torchvision "numpy==2.2.6" --index-url https://download.pytorch.org/whl/cpu --extra-index-url https://pypi.org/simple
venv/bin/pip install "ultralytics==8.4.171" "numpy==2.2.6"
venv/bin/pip install --find-links wheels/aarch64 "ncnn==1.0.20260526" "numpy==2.2.6"
venv/bin/pip install pandas "simplejpeg==1.9.0" "numpy==2.2.6"   # simplejpeg가 없으면 picamera2 import가 깨진다
venv/bin/python -c "import picamera2, ncnn, ultralytics; print('OK')"
```

- 그다음 YOLO에서 만든 모델 폴더를 `~/src/pipeline/weights/ncnn_r4/`에 복사한다([YOLO README §6-2](../YOLO/README.md#6-2-새-모델을-파이로-옮기기)).
- 자세한 내용과 문제 해결은 [pipeline/PI_SETUP.md](pipeline/PI_SETUP.md)를 본다.

## 3. 카메라와 서보 준비

**순서가 중요하다.** 카메라 설정이 바뀌면 색 기준값과 조준 보정을 다시 해야 한다.

### 3-1. 채널 순서 확인 (처음 1회)

빨간 물체를 화면 가운데에 꽉 차게 대고 실행한다.

```bash
python3 01_test_camera.py --truth red        # "가설 A 확정"이면 정상
```

picamera2의 `RGB888` 형식은 이름과 달리 메모리에는 **BGR 순서**로 들어 있다. 이걸 잘못 다루면 검출은 되는데 **빨강과 파랑이 바뀌어 색 판정이 틀린다.**

### 3-2. 카메라 설정 고정

실전과 같은 자리·조명에서 실행하고 `f`를 누른다.

```bash
python3 03_preview.py
```

- 카메라가 화이트밸런스를 맞출 때까지 기다린 뒤 **화이트밸런스(색 게인)를 고정**하고 `03_config/camera_config.json`에 저장한다.
- 노출은 기본적으로 자동으로 둔다(밝기만 `-`/`+`로 조정). 조명이 바뀌어도 사진이 너무 어둡거나 밝아지지 않게 하기 위해서다. 노출까지 고정하려면 `--fixed-exposure`로 실행한다.
- 현재 저장된 값: 1280×960, 색 게인 (R 1.13, B 1.84), 밝기 보정 EV +1.25, 자동 노출.
- 이후 모든 스크립트는 `--load`로 이 설정을 불러와 같은 조건에서 찍는다.

### 3-3. 서보 정면 각도

```bash
python3 98_servo_center.py        # a/d(yaw), s/w(pitch)로 1°씩(대문자는 5°) 움직여 정면을 맞추고 q → 저장
```

SG90은 개체마다 "몇 도가 정면인지"가 다르다. 찾은 값은 `03_config/servo_center.json`에 저장되고 05·07·98이 모두 이 값을 쓴다. 현재 값은 **yaw 95°, pitch 90°**다.

| 서보 | GPIO | 비고 |
|---|---|---|
| yaw(좌우) | 18 | |
| pitch(상하) | 13 | |
| 발사 | 12 | 대기 90° → 발사 160° → 복귀 |

## 4. 데이터 수집

YOLO 학습용 사진은 모두 이 파이에서 찍었다. 해상도는 **1280×960, 회전 없음**으로 통일했다(학습과 실전 조건이 같아야 한다).

### 4-1. 찍는 방법

```bash
python3 05_manual_capture.py --note center_1.5m     # 키보드로 서보를 움직이며 한 칸마다 한 장
python3 05_sweep_capture.py  --note center_1.5m     # 서보가 정해진 범위를 자동으로 훑으며 촬영
```

1. 타겟을 원하는 거리·위치에 세운다.
2. 메뉴에서 라벨을 고른다: `1` 적군 / `2` 아군 / `3` 둘 다(both).
3. `05_manual_capture.py`는 `a`/`d`를 누르면 yaw가 한 칸(기본 2°)씩 움직이며 그때마다 한 장을 찍는다. 화면을 보면서 움직이므로 타겟이 화면 밖으로 나간 사진이 쌓이지 않는다.
4. `05_sweep_capture.py`는 pitch를 몇 단계로 바꾸면서 yaw를 왼쪽에서 오른쪽으로 자동으로 훑는다.
5. 서보를 움직이면 같은 타겟이 화면의 여러 위치에 찍힌다. 그래서 타겟을 손으로 옮기지 않아도 위치가 다양한 사진을 얻을 수 있다.

### 4-2. 저장 형식

```
05_dataset/<라벨>/
  images/*.png
  labels.csv        한 줄 = 사진 1장: filename, label, session, mode(sweep/manual), note,
                    yaw_cmd, pitch_cmd, timestamp, clip_ratio(포화 비율), dark_ratio(어두운 비율), mean_bgr, config_locked
```

- `note`에 **거리와 배치**를 적는다(예: `center_1.5m`, `right_2.4m`). 학습 쪽 도구가 note에서 거리를 읽는다.
- 저장 폴더에 해상도나 회전이 다른 사진이 이미 있으면 **촬영을 멈추고** 폴더 이름을 바꾸라고 알려 준다. 조건이 다른 사진이 섞이는 것을 막기 위해서다.

## 5. 아군과 적군을 색으로 구분하는 방법

**YOLO는 타겟이 어디 있는지만 찾는다.** 아군/적군은 박스 안의 색으로 따로 판정한다. 그래야 색지를 바꿔도 검출 모델을 다시 학습할 필요가 없다.

### 5-1. 색을 고른 과정

1. **배경에 없는 색 찾기** — `04_scene_capture.py`로 실제 장소의 배경 색 분포를 찍어, 배경에 거의 없는 색상 구간을 찾았다.
2. **첫 색지 실패** — 처음 쓴 청록 `#0E7C7B` / 보라 `#5B3FA8`는 카메라에서 너무 어둡게(밝기 V 0.26) 찍혀, 두 색의 차이가 색 흔들림보다 1.5배밖에 크지 않았다(**안전비 1.51**, 기준 3.0 미달). 이 상태에서는 판정이 거의 전부 "판정 불가"가 된다.
3. **후보 색지를 카메라로 직접 측정** — 여러 색지를 한 화면에 놓고 `pipeline/tools/swatch_measure.py`로 각 색의 카메라 속 색(Lab)을 쟀다.
4. **쌍 고르기** — `pipeline/tools/pair_select.py`가 모든 후보 쌍의 거리와 흩어짐을 비교했다. 기준을 통과한 쌍 중에서 **적군 B04 마젠타 `#FF66CC` / 아군 B06 초록 `#4FD95A`** 를 골랐다(이 쌍의 측정 안전비 12.7).
5. **실제 타겟으로 기준값 만들기** — 색칠한 타겟 두 개를 나란히 세워 1.5 / 1.75 / 2.0 m에서 좌우를 바꿔 6장을 찍고 `pipeline/tools/build_color_refs.py`로 기준값을 만들었다 → `pipeline/tools/color_refs.json`.

### 5-2. 판정 방법

[pipeline/tools/target_pipeline.py](pipeline/tools/target_pipeline.py)의 `ColorClassifier`와 [colorlib.py](pipeline/tools/colorlib.py)가 박스마다 다음을 한다.

1. **원본 프레임에서 박스 영역만** 잘라 낸다. 검출을 384 ROI로 했더라도 색은 항상 원본 1280×960에서 잰다.
2. 박스 안에서 **채도가 높은 픽셀만** 고른다(HSV S ≥ 60/255). 박스에는 바닥·막대·배경이 섞여 있어서, 박스 전체 평균을 내면 색이 흐려지기 때문이다.
3. 고른 픽셀의 평균 색을 **Lab 색공간**으로 바꾼다. Lab의 a\*는 초록(−)↔빨강·마젠타(+), b\*는 파랑(−)↔노랑(+)이다. 밝기(L\*)는 조명에 따라 크게 변하므로 쓰지 않고 **a\*b\* 평면의 거리**만 본다.
4. 기준값과 비교한다.

   | | 기준 a\* | 기준 b\* |
   |---|---|---|
   | 아군 (초록) | −30.5 | +22.8 |
   | 적군 (마젠타) | +40.2 | −9.6 |

   더 가까운 쪽으로 판정한다. 두 기준 사이 거리는 **77.8**이다.
5. **판정 불가(unknown)** 조건:
   - 고른 픽셀이 `min_px`(97개) 미만 → `few_px`. 타겟이 너무 작거나 멀거나, 화면 가장자리라 색이 약할 때다.
   - 아군까지 거리와 적군까지 거리의 차이가 `margin`(15.6) 미만 → `ambiguous`. 두 색 사이의 애매한 색이다.
6. **안전 장치**: `color_refs.json`의 안전비가 3.0보다 낮거나 파일이 없으면 기준값을 쓰지 않고 전부 판정 불가로 둔다. 잘못된 기준값으로 아군을 쏘는 사고를 막기 위해서다.

### 5-3. 기준값 측정 결과

| 항목 | 값 | 뜻 |
|---|---|---|
| 두 색 거리(a\*b\*) | 77.8 | 클수록 구분이 쉽다 |
| 사진 간 흔들림 | 아군 2.0, 적군 2.5 | 같은 색이 사진마다 얼마나 달라지나 |
| **안전비** | **34.7** | 거리 ÷ 흔들림. 기준 3.0의 10배 이상이라 여유가 크다(첫 색지는 1.51) |
| 측정 조건 | 1.5 / 1.75 / 2.0 m, 좌우 바꿔 6장, 노출 30 ms, 게인 3.2~3.3, 약 860 lux | |

### 5-4. 판정 모드

`pipeline_config.json`의 `color.mode`로 정한다.

| 모드 | 방법 | 상태 |
|---|---|---|
| `relative` | 총 본체에 붙인 아군·적군·흰색 기준 조각을 **매 프레임** 같이 재서 비교한다. 조명이 바뀌어도 함께 바뀌므로 강하다 | 기준 조각 좌표(`ref_patches`)가 비어 있어서 **아직 쓰지 않는다** → 아래 `absolute`로 자동 대체 |
| `absolute` | `color_refs.json`의 고정 기준값과 비교한다 | **현재 실제로 쓰는 방식** |
| `a_sign` | 기준값 없이 a\* 부호만 본다(a\* > +10 적군, < −10 아군) | 비상용. 마젠타/초록 쌍에서만 맞는다 |

### 5-5. 동작 확인

## 6. YOLO로 타겟을 찾아 맞추는 방법

### 6-1. 한 번의 판정 (target_pipeline.py)

1. **처음 찾기** — 전체 프레임 1280×960을 `960x1280_ncnn_model`로 검출한다. 파이4에서 **약 1.2초** 걸린다(§6-2).
2. **추적** — 한 번 찾으면 다음부터는 타겟 주변 384×384만 잘라 `384x384_ncnn_model`로 검출한다. **약 0.14초**. 잘라 낸 좌표는 원본 좌표로 되돌린다. 타겟이 18×33 px 정도로 아주 작아서, 화면을 줄이지 않고 잘라 내야 정확하다.
3. **신뢰도 조정** — 타겟이 나타날 수 없는 화면 위아래 끝(y 352~672 밖)의 박스는 신뢰도를 절반으로 깎는다. 최종 기준은 conf 0.25다.
4. **색 판정** — §5의 방법으로 박스마다 아군 / 적군 / 판정 불가를 붙인다.
5. **결정**

   | 결과 | 조건 |
   |---|---|
   | `engage` (쏜다) | 적군이 있다. 여러 개면 **박스가 가장 큰 = 가장 가까운** 적군 |
   | `hold` (보류) | 판정 불가인 박스가 **하나라도** 있다(안전 우선) |
   | `no_target` | 박스가 없거나 아군뿐이다 |

6. **조준각 계산** — 타겟을 "조준점"(§7)으로 옮기는 데 필요한 yaw·pitch 각도를 낸다.

### 6-2. 검출 시간 (라즈베리파이4 4GB 실측)

2026-10-04, `pipeline/tools/pi_bench.py --runs 50`으로 쟀다. 모델은 **r3_coco** NCNN FP32이고 ultralytics 8.4.171, ncnn 1.0.20260526를 썼다. 측정 중 성능 제한은 없었다(throttled=0x0).

| 입력 크기 | 용도 | p50 (중앙값) | p95 |
|---|---|---|---|
| 960×1280 | **전체 프레임에서 처음 찾기** | **1,224 ms** | 1,286 ms |
| 736×960 | 비교용 | 694 ms | 724 ms |
| 480×640 | 비교용 | 300 ms | 349 ms |
| 384×384 | **ROI 추적** | **142 ms** | 157 ms |

- p50은 50번 중 가운데 값, p95는 50번 중 느린 쪽 5%를 뺀 최댓값이다. 전처리 + 추론 + 후처리를 모두 포함한다.
- **추적 루프 추정(추론만)**: 전체 1회 + ROI 5회 = **1.93초**, 전체 1회 + ROI 10회 = **2.64초**. 전체 프레임만 5회 돌리면 6.12초이므로, ROI 추적이 약 3배 빠르다. 서보 이동, 흔들림 대기, 촬영 시간은 빠져 있다.
- 측정 중 CPU 온도가 50 → 74 ℃로 올랐다. Pi4는 80 ℃부터 속도를 낮추므로 **연속 운용에는 방열판이나 팬이 필요하다.**
- 프로그램을 처음 켤 때는 torch·ultralytics import와 모델 로딩에 **11~14초**가 걸린다. 그래서 `run_match.py`는 모델을 미리 한 번만 올려 둔다.
- 현재 배포 모델 **r4는 같은 YOLO11n 구조·같은 입력 크기라 비슷할 것으로 예상하지만, 아직 재지 않았다.** 재려면 다음을 실행한다.

  ```bash
  cd ~/src/pipeline && venv/bin/python tools/pi_bench.py --models weights/ncnn_r4 --image samples/enemy_roomA.jpg --runs 50
  ```

### 6-3. 거리 추정

박스 세로 길이 h(px)로 거리를 추정한다. 같은 물체는 멀수록 작게 보이므로 **거리(m) ≈ 59.1 ÷ h**다(1.2~2.4 m 촬영분에서 측정, 잔차 중앙값 1.5 px). 거리는 어느 조준점을 쓸지 고르는 데 쓴다.

### 6-4. 자동 조준·발사 (07_aim_calib.py의 `p` 키)

```bash
cd ~/src && pipeline/venv/bin/python 07_aim_calib.py
```

`p`를 누르면 한 번의 자동 사격을 한다.

1. 전체 프레임을 검출하고 색을 판정한다. **아군으로 판정된 박스만 빼고**, 나머지 중 가장 큰 박스를 고른다.
2. 조준점(보정표의 cx, cy)을 정한다.
3. 타겟이 조준점 **±6 px 안에 들어올 때까지** yaw·pitch를 나눠서 움직인다.
   - 목표를 지나치면 이동 폭을 절반으로 줄여 좌우로 오가며 좁혀 들어간다(최소 0.1°까지).
   - 한 번 움직일 때마다 화면이 실제로 몇 px 밀렸는지 재서 **"1도 = 몇 px"를 스스로 다시 배운다.**
   - 움직인 뒤에는 예상 위치 주변을 다시 검출해 위치를 고친다. 그 박스가 아군으로 판정되면 그 자리에서 멈추고 쏘지 않는다.
4. 확인된 박스가 6 px 안이고 아군이 아니면 발사한다. 발사 서보는 0.5°씩 1초에 걸쳐 천천히 움직여 총 본체가 흔들리지 않게 한다.
5. 모든 시도는 `pipeline/calib/auto_shots.csv`에 한 줄씩 남는다.

> **07과 실전 규칙의 차이**: 07의 `p`는 "아군이 아니면 쏜다"(판정 불가도 쏜다). 대회용 [run_match.py](pipeline/tools/run_match.py)는 `target_pipeline.decide()`를 그대로 써서 **판정 불가가 하나라도 있으면 보류한다.**

### 6-5. 대회용 실행기

```bash
cd ~/src/pipeline && venv/bin/python tools/run_match.py
```

모델을 미리 올리고(약 10초), 빈 프레임으로 한 번씩 돌려 첫 추론의 지연을 미리 치른 뒤, 키(SPACE/Enter)를 기다렸다가 판정 루프를 돈다. 매 프레임 결과는 jsonl 로그로 남는다. 카메라 없이 시험하려면 `--fake samples/enemy_roomA.jpg --start-now --max-frames 5`를 붙인다.

## 7. 조준 보정값을 구한 방법

### 7-1. 왜 보정이 필요한가

카메라는 총에 손으로 붙여서 **총구와 어긋나 있다.** 박스 중심을 화면 정중앙에 맞춰도 탄이 그쪽으로 가지 않는다. 그래서 "타겟이 화면의 **어디에** 보일 때 쏘면 맞는가"(= **조준점**)를 실제로 쏴 보며 찾는다.

### 7-2. 측정 방법 (07_aim_calib.py)

1. 타겟을 정해진 거리(1.5 m, 2.0 m 등)에 세우고, `-`/`+`로 화면의 선택 거리를 맞춘다.
2. 두 가지 방법으로 쏜다.
   - **수동**: `a`/`d`/`w`/`s`로 서보를 움직여 조준하고 `f`로 쏜다.
   - **자동**: `p`로 자동 조준·발사한다(§6-4).
3. **맞았을 때만** `e`를 누른다. 그 순간 타겟이 화면에 보이던 위치(cx, cy)와 박스 높이 h, 서보 각도, 원본 사진이 기록된다.
   - 자동(`p`)으로 맞혔으면 **발사 순간**의 값을 기록한다(`source=auto`). 맞으면 타겟 머리가 떨어져 `e`를 누를 때는 박스가 없을 수 있기 때문이다.
   - 검출이 안 되면 화면에서 타겟 머리 위치를 클릭해 기록한다(`source=click`).
4. `q`로 끝내면 거리별로 기록을 모아 **조준점 표** `pipeline/calib/aim_table.json`을 만든다.
   - 거리마다 cx, cy는 **중앙값**을 쓴다. 잘못 찍은 기록 몇 개에 흔들리지 않게 하기 위해서다.
   - 표는 "박스 높이 h → 조준점 (cx, cy)"이고, 그 사이 거리는 선형 보간한다.
   - 같은 거리에서 표준편차가 15 px를 넘으면 경고한다(서보 재현성이나 카메라 흔들림 의심).

실전에서는 `target_pipeline.py`의 `Aimer`가 이 표를 읽어 **"박스 높이가 h이면 타겟을 화면의 (cx, cy)에 두라"** 로 쓴다.

### 7-3. 각도 환산값 (yaw/pitch)

화면의 px 차이를 서보 각도로 바꾸는 값이다.

| 값 | 어디서 | 현재 |
|---|---|---|
| `yaw_calib` | 수집 사진에서 서보 각도와 타겟 위치 관계를 회귀: **+10.3 px/°** (세션별 7.8~11.6) | `pipeline_config.json`에 `coef [0, 64]`, `sign -1` (화면 반폭 640 px ≈ 64°). **임시값** |
| `pitch_calib` | 같은 렌즈라 약 10.3 px/°로 예상 | 아직 미입력(`null`). 07 자동 조준은 이 값 없이 스스로 배운다 |

## 8. 보정 결과

`pipeline/calib/` 기준(10/6~10/8 측정). git에는 없고 파이에 있다.

### 8-1. 조준점 표 (aim_table.json, 10/8)

| 거리 | 기록 수 (검출 / 클릭) | 조준점 cx | 조준점 cy | 흩어짐 (cx / cy 표준편차) | 측정 h | 예상 h (59.1/d) |
|---|---|---|---|---|---|---|
| 1.5 m | 36 (26 / 10) | 644.6 | 583.9 | 5.9 / 4.5 px | 33.1 px | 39.4 px |
| 1.7 m | 1 (0 / 1) | 635.0 | 588.0 | — | — | 34.8 px |
| 2.0 m | 15 (0 / 15) | 643.1 | 589.2 | 10.4 / 11.5 px | 27.9 px | 29.6 px |

**해석**
- 조준점은 거리와 거의 상관없이 **(약 643, 약 586)** 이다. 화면 중앙(640, 480)보다 **약 105 px 아래**, 좌우는 거의 중앙이다. 즉 이 포탑은 "타겟이 화면 중앙보다 조금 아래에 보일 때" 쏴야 맞는다. 카메라가 총구보다 위에 붙어 있기 때문이다.
- 1.5 m와 2.0 m의 조준점 차이(cy 5 px)는 흩어짐보다 작다. **1.5~2.0 m에서는 조준점 하나로 충분하다**는 뜻이다.
- 2.0 m 기록은 전부 클릭이고 흩어짐도 1.5 m의 약 2배라서 1.5 m보다 덜 정확하다.
- 1.7 m는 기록이 1개뿐이라 참고값이다.
- 측정 h가 예상(59.1/d)보다 작다. 특히 1.5 m는 33.1 vs 39.4다. 59.1은 **색칠 전** 타겟으로 잰 계수다. 색칠 후 타겟과 r4 모델 기준으로 **다시 재야 한다.**

### 8-2. 자동 조준·발사 기록 (auto_shots.csv, 10/6)

전체 92회 시도의 결과는 다음과 같다.

| 결과 | 횟수 | 뜻 |
|---|---|---|
| 발사 (조준점 ±6 px 안으로 수렴) | 54 | |
| 발사 (이미 ±6 px 안이라 바로 발사) | 4 | |
| 수렴 실패 | 7 | 놓치거나 끝까지 못 맞춤 |
| 보류 / 아군만 / 적군 없음 | 16 | 쏘지 않음(정상 동작) |
| 조준점 없음 | 6 | 보정 기록이 없는 거리 |

- **명중률(기록 기준)**: 10/6 20:25~21:30 사이에 자동 발사 40회 중 명중으로 기록(`e`)된 것이 **26회, 약 65%** 다. 맞았는데 `e`를 누르지 않은 경우가 있으면 실제보다 낮게 잡힌다.

## 10. 주의할 점

1. **카메라는 한 번에 한 프로그램만** 쓸 수 있다. 사용 중인지 확인하려면 `fuser -v /dev/video0`.
2. **카메라 설정(03_config)을 바꾸면 색 기준값이 무효**가 된다. 화이트밸런스나 밝기를 바꿨으면 §9의 4번부터 다시 한다.
3. **카메라를 건드리면 조준점 표가 무효**다. 보정 전에 카메라가 총에 단단히 고정됐는지 확인한다.
4. 07에서 `e`는 **실제로 맞았을 때만** 누른다. 빗나간 자세가 기록되면 표가 틀어진다.
5. 07의 발사는 시작 후 5초 동안 잠겨 있다(서보 초기화 중 오발 방지). 시작·종료 때 발사 서보는 항상 대기 위치(90°)로 간다.
6. 키 입력은 **영문 입력 상태**에서만 전달된다.
7. 화면 **왼쪽 끝**은 렌즈 가장자리라 색이 약하다(고채도 픽셀이 중앙보다 약 35% 적다). 검출은 되지만 판정 불가가 나기 쉽다.
8. `pipeline/tools/`의 원본은 이 파이다. 학습 서버에서 고치지 말고 여기서 고친 뒤 [pipeline/tools/CHANGELOG.md](pipeline/tools/CHANGELOG.md)에 한 줄 적는다.
